# 任务可靠性与陪玩交互修复

本次发布集中处理猫娘执行指令时停不下来、任务未达标却报告完成、工具与配方判断不准确，以及跟随、自主行动和对话相互干扰的问题。更新同时涉及 Python 插件与 NekoTerrariaLink Mod 源码。

## 指令、停止与真实结果

- 停止指令优先处理，不等待意图 LLM，也不被待回答的问题吞掉；取消尚在解析或排队的旧指令，并使 Mod 已排队的动作、拾取和合成失效。
- 区分长期循环、前台任务和自主行动，避免旧任务退出期间重新抢占动作。只有确认任务退出并收到游戏动作停止回执后，才报告完全停下；断线或退出未完成时说明尚未确认。
- 采集、转交、存箱、合成和导航依据实际数量与动作回执报告结果，数量不足、只开始执行或仅完成部分步骤都不能说整项任务完成。
- 历史指令的语义相似匹配只提出建议，需要主人确认；否定、等待和过期询问不会触发旧任务。明确的多步指令保留完整任务链，无法识别的步骤不会被替换成走过去或静默丢弃。

## 跟随、导航与自主行动

- 普通跟随和战斗导航默认不搭方块，减少在高空平台附近误放方块。允许搭建的脱困路径限制消耗数量，使用真实库存，避开角色、NPC、已有方块和收藏材料。
- 主人位置丢失时停止追逐旧坐标；空闲跟随连续失败后等待位置变化，减少持续撞墙与无效重试。调整路径点到达判断、脚底坐标和跳跃控制，移除导航直接强写速度的处理。
- 修复自主动作权限判断导致自身被阻塞的问题，完善任务接管、重连与复活后的状态清理，减少过期动作恢复和不同游戏逻辑争抢控制。
- 战斗与 Boss 击杀回报使用游戏侧真实 NPC 死亡事件，目标离开可见范围或暂时消失不再直接算击杀。

## 物品、配方与工具准备

- 物品识别结合游戏注册表、真实物品 ID 和完整名称；配方保留实际配方索引、合成环境、批次产量与配方组替代材料，减少同名物品和模组物品误判。
- 缺工具时依据真实配方尝试准备材料。缺木材先查可用箱子，再判断是否无法继续，避免箱子明明有木材却因缺斧头直接失败。
- 递归制作中间材料按所需产物数量准备原料，完成后重新核对实际背包；保留深度和循环限制，不凭空生成工具，也不反复要求用尚未制作的斧头砍树。
- 加强箱子物品转移的异常回滚、堆叠数量处理和拾取后的库存同步，避免未确认转移却报告成功。

## 背包整理与陪玩对话

- 采集后检查背包空间，空间不足时通过宿主 LLM 告诉主人需要整理，再尝试回基地、存箱并核对库存变化，之后尝试返回主人附近。也可使用“回家存箱”“整理背包”安排整理。
- 回家、存箱或返回主人失败会说明困难并暂停相关采集，不声称已经整理完成；停止指令可以中断相关流程。
- 夸奖和责备影响情绪，回应由宿主人设生成；移除意图解析器额外抢答，已提交的闲聊和确认问题不再被工具结果重复播报。
- 检查宿主消息受理结果，明确区分受理与实际播放。宿主拒收时，任务事实、确认问题和紧急短句可以回退到游戏聊天；内部提示词和静默上下文不会原样显示。
- 紧急回应使用独立额度，绕过普通聊天静默窗，避免重复扣除额度。没有有效状态或角色死亡时不主动闲聊，危险衔接使用当前任务和生命状态，不承诺恢复已经停止的任务。
- 背包变化对比整份库存，启动时已有物品不当作新发现；不把猫娘自己的收获说成主人的收获，也不凭库存增长编造采集来源。

## TCP 与运行生命周期

- Mod 使用有界后台 FIFO 队列发送消息，避免游戏主线程等待 socket；队列设有容量限制，防止发送积压无限增长。
- 请求按请求 ID 匹配回执；断线清理、异步事件回调和任务退出保留真实失败信息，减少旧连接响应、排队动作及过期状态影响当前任务。

## 下载与使用说明

这是源码发布，GitHub Release 提供对应标签的源码压缩包。插件和 Mod 源码需要配套使用：将 `mod/NekoTerrariaLink/` 放入 tModLoader 的 `ModSources`，自行构建并启用，再按使用指南配置插件。

本次没有编译或上传新的 `.tmod`，也没有提供包含新编译 Mod 的 `.neko-plugin` 安装包。仓库 `mod/tModLoader/Mods/` 中保留的 `.tmod` 并非由本次源码重新构建，不能用它判断这些 Mod 修复是否生效。

仅进行了静态语法与差异检查，没有运行自动化测试、启动 Terraria 或验证游戏内效果。水中脱困、复杂坑洞寻路和不同模组组合下的行为仍需实际验证，本次发布不代表全部玩法问题已经解决。
